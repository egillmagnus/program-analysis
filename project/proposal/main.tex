\section{Introduction}

\paragraph{Context}
Runtime errors that occur only for particular input values are hard to find
by testing. In a dataset of buggy competition programs,
\citet{prenner2023runbugrun} find that
\texttt{ArrayIndexOutOf\-BoundsException} is the most common exception in Java,
at 36.99\% of thrown exceptions, and \texttt{ArithmeticException} accounts for
5.23\%. In \cref{lst:example}, taken from the JPAMB
benchmark\footnote{\url{https://github.com/kalhauge/jpamb}}, the first method
divides by zero for a single input, and the second fails its assertion for 32
of the $2^{32}$ possible inputs. We study JPAMB's prediction problem: given a method $m$ and an outcome $o$
(\texttt{ok}, an error such as $\mathrm{err}(\text{`divide by zero'})$, or
non-termination \texttt{*}), decide whether some $\tau \in \mathrm{Sem}(m)$
ends in $o$.

\begin{lstlisting}[float, label=lst:example, caption={Two JPAMB methods in which an error occurs only for specific values.}]
public static int divideByNMinus10054203(int n) {
  return 1 / (n - 10054203);       // divides by zero only for n = 10054203
}
public static void divisionLoop(int n) {
  for (int i = 0; i < 5; i++) { n /= 2; }
  assert n != 32;                  // fails only for 1024 <= n <= 1055
}
\end{lstlisting}

\paragraph{Gap}
No single standard technique answers this question in both directions.
Interval analysis can prove that an outcome is unreachable, but otherwise only
answers ``maybe'': in \cref{lst:example} the interval of each checked
expression contains the error value. Dynamic analysis can only show that an outcome occurs, and random testing
finds the first error with probability $2^{-32}$ per execution. Symbolic
execution solves for an input directly, but must bound the search in methods
with loops, and a search that stops at the bound proves nothing about longer
traces. What is missing is a prediction for each outcome that is backed on both
sides: a proof over all traces for ``no'' and a concrete input for ``yes''.

\paragraph{Innovation}
Our key insight is that interval analysis and symbolic execution fail in
complementary ways, so we integrate them such that each analysis uses the
result of the previous one:
\begin{enumerate}
  \item A \textbf{syntactic analysis} collects the constants $K$ in the bytecode,
    such as \texttt{10054203} and \texttt{32}, as thresholds for the widening $\nabla$, which keeps these bounds while still
    terminating.
  \item An \textbf{interval analysis} computes a fixed point that
    over-approximates $\mathrm{Sem}(m)$ and excludes every outcome it never
    reaches.
  \item \textbf{Symbolic execution} explores only branches reaching an
    instruction where the fixed point admits the outcome, and asks Z3 to solve
    the path constraint $\psi$ with the error condition.
  \item The \textbf{interpreter} replays each model; a trace ending in the outcome
    witnesses it.
\end{enumerate}
To handle its limitations, symbolic execution unrolls loops and inlines calls
up to a bound $k$, and a path beyond $k$ or a solver timeout leaves the outcome
undecided. Integers are 32-bit bit-vectors and arrays use Z3's array theory;
objects, strings and floats are out of scope. An acyclic method without calls
cannot produce \texttt{*}, and if the fixed point reaches no final state,
\texttt{*} occurs. Otherwise \texttt{*} stays undecided, as termination is
undecidable in general and ranking functions are out of scope.

\paragraph{Evaluation}
The pipeline gives each pair $(m, o)$ one verdict: witnessed, excluded or
undecided. The gap is closed if (i) every witness replays and no excluded
outcome occurs in JPAMB's listed cases, and (ii) the pipeline decides more pairs
than the interval analysis and symbolic execution run separately. We also measure how pruning reduces explored paths, solver calls and running
time, and
compare with random fuzzing and small-value testing. Besides JPAMB, whose
\texttt{@Case} annotations serve only for evaluation, we write 24 methods, four
in each of six categories (magic constants, arithmetic chains, input-changing
loops, two-parameter conditions, nonlinear arithmetic, arrays), and submit five
to JPAMB. Ablations remove the pruning or $K$, and for random fuzzing we report the mean and standard deviation over 10 runs.
